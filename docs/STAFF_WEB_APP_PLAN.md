# 교직원용 Google 업무·수업 도우미 웹앱 계획

작성일: 2026-09-26 · 상태: 로컬·배포 웹앱 코드 구현 및 로컬 실연동 검증. 공개 배포용 계정 설정 대기.

구현된 기능·운영 제한·검증 방법은 [웹앱 실행 및 운영 안내](WEB_APP_OPERATIONS.md)를 참고한다. 아래 문서는 초기 제품 계획이며 조직 템플릿·대시보드 등 후속 기능까지 포함한다.

## 1. 제품 목표

설치 없이 브라우저에서 Google 계정으로 로그인한 교직원이 수업 자료와 행정 문서를 만들고, 내용을 미리 확인한 뒤 자신의 Drive와 Classroom에 저장한다. 기존 `edu-workspace-mcp`는 계속 독립적으로 배포한다. 웹앱과 MCP가 Google 작업 규칙, 문서 템플릿, 승인 절차를 공유한다.

**첫 출시의 성공 경험:** “5학년 과학 소화와 순환”을 입력하면 성취기준 후보를 확인하고, 수업안·학습지·슬라이드·퀴즈 초안을 한 화면에서 검토한 뒤 Drive에 저장한다. Classroom 게시는 별도 확인을 거친다.

## 1-1. 개인 로컬 앱과 공개 배포 앱

두 제품을 복사해 따로 개발하지 않고, 같은 저장소의 공통 코어와 화면을 두 실행 환경에서 사용한다. 기존 MCP도 공통 코어를 호출하는 별도 진입점으로 유지한다.

| 구분 | 개인 로컬 앱 | 공개 배포 앱 |
| --- | --- | --- |
| 접속 | 본인 컴퓨터의 localhost 화면, 처음에는 시작 명령 하나 | 설치 없는 웹 주소 |
| 계정 | 현재 데스크톱 OAuth와 로컬 토큰 저장소 재사용 | 별도 Web OAuth client와 사용자별 세션·암호화 토큰 저장소 |
| AI 키·비용 | 본인 Gemini/GPT 키를 로컬 설정에 보관 | 운영자의 서버 키, 사용자별 사용량·요금 제한 |
| 파일 | 로컬 HWP/HWPX 선택과 Drive 파일 선택 | 브라우저 업로드와 Drive 선택, 크기·시간·동시 처리 제한 |
| 고급 문서 기능 | 로컬 kordoc 처리, 개인 서식·템플릿, 시험 기능 | 검증된 변환·템플릿만 공개 |
| 기록 | 기기 안의 최근 작업·초안 | 계정별 최소 작업 상태, 삭제·보관 정책 |
| 배포 | 개인용 업데이트와 백업 | 장애 감시, 속도 제한, 관리자 안내, OAuth 검수 |

**같은 결과를 보장할 기능:** 수업안·학습지·슬라이드·퀴즈 생성, 성취기준 확인, HWP↔Google 문서 변환, 초안 미리보기, Drive 저장, Classroom 게시 전 확인. 개인용의 실험 기능은 기능 플래그로 관리해 공개 앱에 검증 없이 노출되지 않게 한다.

개인 로컬 앱에서도 Gemini/GPT API를 호출하면 입력 내용은 해당 AI 제공자로 전송된다. 파일을 kordoc으로 로컬 변환하는 단계와 AI 생성 단계를 화면에서 구분한다.

## 2. 사용자 화면

1. **시작 화면:** “수업 자료 만들기”, “업무 문서 만들기”, “한글 문서 변환”, “평가·현황 정리” 카드와 실제 예시. 최근 작업, Google 연결 상태, 개인정보 안내를 보여준다.
2. **단계별 작성:** 학년·교과·주제 또는 업무 유형을 고르고, 필요한 항목만 묻는다. 자연어 요청은 선택 입력이다.
3. **미리보기·수정:** AI 초안을 문서별로 확인하고 직접 고친다. 출처가 있는 성취기준, 표, 문항 정답·배점, 첨부 대상이 한눈에 보인다.
4. **저장·배포:** “내 Drive에 저장”으로 파일을 만들고 링크를 모아 보여준다. Classroom 게시·외부 공유는 대상과 권한을 다시 확인받는다.
5. **예시 모음:** 수업 패키지, 학습지, 수행평가 루브릭, 형성평가 퀴즈, 가정통신문 초안, 회의록, 출장 보고, HWP↔Google Docs를 “예시로 시작하기” 버튼으로 제공한다.

## 3. 첫 출시 범위

| 우선순위 | 기능 | 현재 자산 |
| --- | --- | --- |
| 필수 | 수업안·학습지·슬라이드·퀴즈 묶음 생성 | 기존 Docs/Slides/Forms 생성, 성취기준 검색 |
| 필수 | HWP/HWPX→Google Docs, Google Docs→HWPX | kordoc 4.15.4 연동 도구 |
| 필수 | 일반 업무 문서 초안·Google Docs 저장 | 일반 문서 생성 도구 |
| 필수 | Classroom 과제 초안 및 게시 전 확인 | 기존 승인 규칙 |
| 후속 | 평가 관리 시트, 제출 현황 대시보드 | 기존 Sheets/Classroom 도구. 학생 정보 정책 검증 뒤 웹에 노출 |
| 후속 | 학교별 공유 템플릿, 공동 작업, 조직 관리자 기능 | 신규 설계 필요 |

첫 버전에서는 학생 실명·성적·상담 기록을 AI에 전송하는 기능을 제공하지 않는다. 그런 자료를 다루는 기능은 별도 데이터 처리 기준과 학교·기관 승인 범위를 확인한 뒤 추가한다.

## 4. 기술 구조

```text
교직원 브라우저
  → 웹앱 UI (카드·입력·미리보기·승인)
  → 웹 API (사용자 세션, 사용량 제한, 작업 기록)
  → 공통 Workspace 서비스
       ├ Google OAuth/Web client → Docs·Sheets·Slides·Forms·Drive·Classroom
       ├ kordoc → HWP/HWPX 문서 변환
       └ AI 어댑터 → Gemini 기본 / GPT 선택형
기존 MCP stdio → 같은 공통 Workspace 서비스
```

- 현재 `src/server.ts`에 묶인 도구 로직을 공통 서비스로 추출한다. MCP는 그 서비스의 한 어댑터로 유지한다.
- 현재 OAuth 토큰은 사용자 컴퓨터의 단일 파일, 승인 ID는 프로세스 메모리에 있다. 웹에서는 사용자·조직별로 분리된 토큰 저장소와 만료되는 일회성 승인 저장소가 필요하다.
- 브라우저에는 Gemini/OpenAI API 키와 Google 갱신 토큰을 보내지 않는다. 서버가 AI와 Google API를 호출한다.
- 초기 배포 후보는 Node 런타임을 쓰는 Google Cloud Run 단일 웹 서비스다. kordoc의 문서 처리를 서버에서 실행하고, 작업 시간이 긴 변환은 작업 큐로 옮긴다. 운영 계정·비밀 관리·최소한의 작업 상태 저장소를 둔다.
- MCP 패키지의 릴리스와 웹앱 배포를 분리한다. 공통 서비스의 계약 테스트로 두 경로의 결과가 같은지 검증한다.

## 5. AI 사용 방식

1. **Gemini 기본:** AI는 수업안/학습지/퀴즈 등의 구조화된 초안만 만든다. 앱은 JSON 스키마와 Zod로 검증하고, 성취기준 원문은 기존 검증 데이터에서 붙인다.
2. **GPT 고급 개선:** 사용자가 “표현 다듬기” 또는 “수업 설계 개선”을 선택했을 때만 호출한다. 기존 초안과 개선안을 비교해 보여주고, 추가 비용을 사전에 표시한다. 어느 제공자에게 내용이 전송되는지도 표시한다.
3. **문서 생성은 결정적 처리:** AI가 Google API를 직접 임의 호출하지 않는다. 검증된 초안을 앱의 생성 서비스에 전달한다.
4. **개인정보 기준:** Gemini 무료 등급에는 실명·성적·상담·비공개 학교 문서를 보내지 않는다. 무료 등급은 가상 데이터와 일반 수업 주제 시범용으로 제한한다. 학교 현장 데이터를 쓰는 단계에서는 유료 데이터 처리 조건과 기관 정책을 검토한다.
5. **비용 관리:** 모델명은 설정으로 교체 가능하게 하고, 사용자별 일일 사용량·동시 작업 수·최대 입력 길이를 제한한다. 무료 할당량 초과 시 무한 재시도하지 않고 다음 사용 가능 시점을 안내한다.

## 6. 배포 순서

| 단계 | 산출물 | 통과 기준 |
| --- | --- | --- |
| 0. 교직원 검증 | 교사·행정직원 5~10명 인터뷰, 상위 업무 3개와 예시 확정 | 첫 화면의 목적형 메뉴와 입력 항목 확정 |
| 1. 공통 코어 분리 | 사용자별 인증 컨텍스트, Google 서비스·승인 저장소 인터페이스, MCP 회귀 테스트 | 기존 31개 MCP 도구가 같은 계약으로 동작 |
| 2. 비공개 웹 베타 | 로그인, 예시 모음, 수업 패키지, HWP 변환, 미리보기·Drive 저장 | 시험 계정에서 실제 양방향 변환과 파일 생성 성공 |
| 3. 교직원 파일럿 | 사용성 개선, 업무 문서, Classroom 초안, 오류 복구·사용량 계측 | 대표 업무 3개를 안내 없이 완수하고 중복 생성·무단 게시 0건 |
| 4. 공개 배포 | 운영 도메인, 개인정보·삭제 안내, OAuth 검증/기관 관리자 안내, 지원 채널 | 공개 계정·학교 계정 테스트와 배포 체크리스트 통과 |
| 5. 고급 기능 | GPT 선택형 개선, 학교별 템플릿, 평가/제출 대시보드 | 제공자별 데이터 전송 동의와 비용 표시 검증 |

1인 개발 기준으로 0~2단계는 대략 4~6주, 파일럿과 공개 준비는 검증 일정에 따라 추가로 잡는다. 이는 일정 추정이며 Google OAuth 검수와 학교 관리자 허용 여부가 공개 시점을 좌우할 수 있다.

## 7. 공개 전 결정할 사항

- 첫 배포 대상: 소수 학교 비공개 파일럿인지, 누구나 가입하는 공개 서비스인지.
- 운영 주체와 비용: Gemini 유료 전환 시 과금 주체, 사용자별 한도, GPT 고급 기능의 결제 방식.
- 데이터 범위: 학생 정보·학교 비공개 자료의 허용 여부, 보관 기간, 삭제 요청 처리, 기관 관리자 승인.
- 결과물 품질 기준: 수업안·학습지·HWPX의 검수용 실물 샘플과 서식 합격 기준.
